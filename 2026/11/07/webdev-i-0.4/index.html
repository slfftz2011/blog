Web 开发系列教程：从入门到入土

第一部：页面结构与样式基础


第四节：高效利用 AI 做静态开发

经过前三节，你已经知道 Web 开发大概是怎么回事，环境也搭好了。按理说该直接开讲标签和样式了，但我觉得有件事得先聊：在这个时代学 Web，绕不开 AI，但怎么用 AI，差别很大。

先说结论：用好 AI，事半功倍；用不好，事倍功半，还可能给自己埋雷。

为什么这么说？大概有这么几层。

第一，生成式 AI 大模型这两年普及得很快，不少团队已经开始用 VibeCoding 的方式做项目——简单说，就是靠自然语言描述需求，让 AI 边聊边写代码。没碰过编程的人也能做出像样的页面，创作门槛确实降了。

第二，AI 在前端开发里确实有优势：设计稿转代码、生成页面骨架、审查代码、跑测试，这些“可描述、可验证”的环节，AI 能把成本压下去不少，把人从重复劳动里解放出来，去做架构判断和最终验收。

第三，AI 见过的东西多，能帮你提前调研、参考别人的做法，把一些固定套路快速搭出来。说人话就是：它是个见多识广的助手，但拿主意、做验收的还得是你。

第四，同样一个 AI，不同人用出来效果差很远。会用的人能把需求说清楚，能指挥 AI 干活，也能识别它什么时候在胡说，把坑补上。AI 是工具，不是替身。

所以这一节的重点不是“AI 有多强”，而是怎么把 AI 变成助力，而不是拐杖。

别把 AI 当枪手

AI 能帮你开发，这不假。但盲目信任、不独立思考、把 AI 当枪手，迟早要还。下面几个雷区，一定要避。

1. 一口气吃成胖子

AI 的上下文有限，写代码时尤其明显。几个文件下来，它可能连最初的需求都忘得差不多了。

如果你一上来就让 AI“给我做一个完整项目”，甩过去一大堆需求，别说 AI，人看了也头晕。结果往往是：做出来的东西跟你要的背道而驰；出了问题你也不知道从哪儿问起；一次性复制下来，你自己也维护不了、分不清。

有好想法是好事，但更重要的是拆目标、分段做。现在的 Agent（智能体，可以理解成能自己拆任务、按步骤执行的 AI 助手）大多有个 Plan 模式——先根据你的需求列一份 TODO，再一步步施工。你也要模拟这个过程：把大任务拆成子问题，按重要性排序，依次交给 AI。或者更省事：把需求丢给 AI，让它先帮你列 TODO。

让 AI 一个文件一个文件地输出，不仅方便你复制，更方便快速定位问题。项目一大，连从哪儿查起都找不到，那才叫难受。

2. 不理解，直接 Ctrl+C + Ctrl+V

这是新手最容易踩、也最隐蔽的坑。AI 给你一段代码，能跑，页面也出来了，看着挺美。你复制、粘贴、保存、刷新，一气呵成。但问你“这段代码在干嘛”，你只能回一句：“不知道，反正它能跑。”

问题就出在这句“反正它能跑”上。

代码不是一次性用品。今天能跑，不代表明天改个需求还能跑；这台电脑能跑，不代表换个浏览器还能跑。等你哪天想改个颜色、挪个位置、加个按钮，面对那坨自己没读过的代码，你会突然发现：你拥有了一个能跑的东西，但你不拥有它。就像你租了辆车，钥匙在手里，引擎盖怎么开、备胎在哪、仪表盘亮红灯什么意思，一概不知。平时开着没事，一旦抛锚，只能原地打电话。

更麻烦的是，AI 给的代码不一定对。它可能用了过时的写法，可能埋了个安全漏洞，可能在你没注意的地方写了个 eval()，或者把 API Key 硬编码在明面上。你不理解，就发现不了。等出了事，AI 不会替你背锅，浏览器也不会。躺枪的只有你。

还有一种情况更常见：代码能跑，但跑得不对。比如它确实把按钮变蓝了，但用的是一种你完全没法维护的方式——到处 !important、十个 div 套娃、样式全写在行内。你现在看着还行，等页面复杂一点，想改一处，牵一发而动全身。回头再找 AI，它可能给你另一个“能跑”的补丁，越补越乱，最后变成一座你不敢碰的积木塔。

那怎么办？很简单：让 AI 解释，你负责理解。

AI 最擅长的其实不是替你写代码，而是当你的翻译官。你复制一段看不懂的代码，直接问它：“逐行解释这段代码在干什么，用小白能听懂的话。”它会告诉你每一行在做什么、为什么这么写、有没有坑。你读完，再决定要不要用、怎么用。

更进一步，你可以让 AI 给代码的同时附带解释。提问时加一句：“给我代码的同时，用注释说明每一部分的作用，并告诉我哪些地方我以后可能需要改。”这样你拿到的就不只是一坨能跑的字符，而是一份你能读懂的方案。

记住一个判断标准：如果你没法用一句话说清这段代码在干什么，就先别把它放进项目里。不是不能抄，是不能“闭眼抄”。抄之前，至少让 AI 讲明白。讲明白了再抄，那叫借鉴；讲不明白就抄，那叫埋雷。

3. 把 AI 当搜索引擎，问完不查文档

AI 最会的一件事，就是产生“AI 幻觉”——一本正经地胡说八道。标签名、属性名、CSS 值，它张口就来，说得头头是道，但有些东西根本不存在。你拿它当 MDN 用，它拿你当试验田。

比如它告诉你“用 <h11> 做小标题”“写 display: flexbox 就能横向排列”“给图片加个 alt-text 属性”。听着挺像那么回事，你去 MDN 一搜，搜不到——那就是幻觉编出来的。正确写法可能是 <h6>、display: flex、alt。差一个字母，浏览器就不认。

所以规矩很简单：AI 给方向，MDN 给准话。 它说的标签、属性、写法，花三十秒去 MDN 搜一下。搜得到，继续用；搜不到，别信。这一步不丢人，老手也这么干。省这三十秒，后面可能搭进去半小时。

4. 只让 AI 改，不自己跑

AI 说“已经修好了”，你就信了，文件一保存，看都不看。这是把方向盘交出去。

代码是给浏览器跑的，不是给 AI 跑的。它说行不算行，浏览器说行才算行。每让 AI 改一次，至少做三件事：保存、刷新、按 F12 看 Console。页面没变、布局崩了、红字一片，都说明它没改对。更常见的是它只给你一句“把这里替换成下面这段”，你连替换到哪都没看清就粘了，粘完发现多了一层括号。

而且别忘了，AI 也可能幻觉自己已经改对了。它看不见你的屏幕，只能根据你贴的文字猜。你贴得不全，它猜得不准，最后它信心满满地说“好了”，你一看，还是老样子。记住：AI 负责给方案，你负责验收。 不验收，等于没改。它再聪明，也看不见你屏幕上的页面；能看见的，只有你。

这不能那不能，怎么用？

说完雷区，想必你也有疑惑：这不能做那不能做，那我还怎么用？别急，看下面几条小建议。

1. 看不懂？最好的老师

AI 最值钱的地方，不是替你写，是替你讲。你从 MDN 抄了一段示例，从别人项目里截了一段代码，或者 AI 刚给你生成了一段，你看得半懂不懂——这时候别硬猜，直接把它贴给 AI，加一句：

逐行解释这段代码在干什么，用小白能听懂的话。遇到专业术语先解释再用。最后告诉我，如果我想改颜色/改文字/挪位置，应该动哪一行。

它就会从“这行是干嘛的”讲到“你想改哪里动哪里”。你读完，再回浏览器里改一改、跑一跑，这才叫真看懂。看不懂就问，问完就改，改完再看——这个循环走三遍，比背十遍标签表都管用。

2. 新想法，TODO + 基本结构

脑子里有个页面想法，别一上来就让 AI“给我写个完整的”。先让它帮你拆：

我想做一个个人主页，包含：顶部导航、一张头像、一段自我介绍、三个作品卡片、底部联系方式。请先帮我列一个 TODO 清单，按从易到难排序，每一步只做一个小块，不要直接写完整代码。

拿到 TODO，你挑第一步让它做，做完你看一遍、跑一遍、改一改，再做第二步。一个文件一个文件来，一个模块一个模块来。 这样每一步你都知道自己在干什么，出了问题也知道去哪找。AI 不会一次给你一座城堡，但可以陪你一块砖一块砖地砌。

3. 样式与布局效果，如何清晰表述你的需求

“按钮好看点”“页面大气些”“颜色柔和一点”——这种话 AI 听不懂，因为它不知道你心里的“好看”长什么样。你得把感觉翻译成能落到代码上的描述。

别只说“按钮不好看”，要说：

现在按钮是灰色背景、黑色文字、直角。我想要：背景改成 #2563eb，文字白色，圆角 8px，鼠标移上去背景变深一点，内边距上下 10px、左右 20px。只给我 CSS，告诉我加在哪。

也别只说“布局乱”，要说：

现在三个卡片竖着排，我想让它们在宽屏上横着排、每行三个，窄屏上竖着排。用 Flexbox 或 Grid 都行，给我最简单的写法，并解释每一行在干嘛。

说不清具体数值也没关系，可以给参照：“像 GitHub 首页那种卡片”“像苹果官网那种大标题”。AI 能根据参照物猜个八九不离十，你再在 DevTools 里微调。描述得越具体，它返工越少；你验收得越仔细，下次描述越准。

多看一眼，实践出真知

AI 给的东西，别急着信。它说“好了”，你要自己看一遍才算数。检验就三步，花不了两分钟：

第一步，浏览器里跑一遍。 保存、刷新，看页面到底变成什么样。AI 描述得再美，浏览器里没变就是没变。这一步最直接，也最容易漏——很多人粘完代码就关对话框，结果文件根本没保存。

第二步，MDN 对一遍。 AI 提到的标签、属性，挑一两个去 MDN 搜一下。搜得到，说明它没编；搜不到，那就是 AI 幻觉，别用。尤其那些你没见过的写法，越像那么回事，越要查。

第三步，Console 看一眼。 按 F12，看有没有红字。页面看着正常，不代表底层没报错；报错了也不一定影响显示，但迟早会咬你一口。

三步走完，你才算真正“验收”了 AI 的答案。多看一眼，省的是后面半小时的排查。

学写提示词

提示词不用背模板，但值得知道一段“好提示词”由哪几块拼起来。下面这七块，不是每次都写全，但心里要有数——缺哪块，AI 就在哪块瞎猜。

一、你的身份。 先告诉 AI 你是谁。是刚学两天的小白，还是写过几个页面的人？这决定了它讲得多细。你说“我是零基础”，它就会少甩术语；你说“我懂基础 CSS，只是不熟动画”，它就不会从标签讲起。

二、给 AI 的角色。 给它一个角色，它就会调用对应的经验。“前端开发”关注代码结构和兼容性，“UI 设计”关注视觉比例和配色，“调研员”会先帮你比较方案再动手。同一个需求，换角色，输出差很远。

三、使用场景。 这个东西放在哪、给谁看、为什么要做。比如“这是一个个人主页的欢迎区”，和“这是一个儿童教育网站的欢迎区”，出来的风格完全两码事。

四、任务总体需求。 一句话说清最终目标。比如“做一个纯 CSS 的火山喷发场景动画”。目标要能验收——“做得好看”没法验收，“火山口有光、有熔岩流、有飘动的烟”能验收。

五、具体需求。 敲细节：颜色、尺寸、动效时长、循环方式、要不要交互。细节越具体，返工越少。

六、确认流程。 告诉 AI 怎么和你配合。推荐固定三步：先列 TODO → 再分块写代码 → 最后给我验证清单。别让它一口气全写完，你没法验收。

七、特殊开发细节或注意事项。 用什么语言、要不要注释、支持哪些浏览器、能不能用外部库、代码放哪个文件。这一块最容易漏，也最容易出岔子——比如它给你一段 React，你打开的是纯 HTML 文件，直接白屏。

七块拼起来，就是一段能用的提示词。下面拿一道火山喷发动画练手。

小练习：火山喷发

题目背景：为个人主页顶部做一个循环播放的火山喷发场景。画面要有立体感，喷发要猛烈。纯展示，不可交互（加分项除外）。

技术限制：单个 index.html；使用原生 HTML + CSS + JavaScript；绘制使用原生 Canvas 2D API；不使用 Three.js、p5.js 等第三方库；不使用外部图片、字体、音频；只需兼容 Chrome / Edge 最新版。

任务要求（必做）：

  1. 画布逻辑尺寸 960 × 540，居中显示，超出容器部分隐藏；按 devicePixelRatio 缩放，画面不模糊。
  2. 山体呈火山锥形，有立体感：左侧受光、右侧背光，火山口画成透视椭圆，山脚有地面阴影。
  3. 粒子采用伪 3D：每个粒子有 x / y / z 三个坐标，z 表示深度；绘制时按 z 排序，近大远小、近亮远暗，形成前后遮挡。
  4. 主喷发周期性爆发，每次喷出大量高速粒子，受重力影响呈抛物线；粒子可飞出画布顶部后再落回。
  5. 每次爆发伴随少量熔岩弹：颗粒更大、更亮，带拖尾，落回山体或地面。
  6. 爆发瞬间火山口强闪光，并出现一圈向外扩散的冲击波环。
  7. 火山灰持续向上扩散：暗色粒子逐渐变大、变淡，遮挡部分背景。
  8. 爆发瞬间画布整体震动，幅度随时间衰减。
  9. 动画持续运行，帧率稳定；使用 requestAnimationFrame 和 deltaTime，不依赖固定帧率。
  10. 关键逻辑加中文注释。

加分项（任选，多做多得）：

  • 点击画布触发一次额外大爆发。
  • 熔岩弹落地产生溅射小粒子。
  • 火山口闪光动态照亮附近山体，山体亮度随闪光变化。
  • 背景有星空，火山灰经过时遮挡星星。
  • 使用粒子池复用粒子，避免频繁创建销毁。
  • 窄屏下画布等比缩小，不出现横向滚动条。
  • 页面切到后台时暂停动画，切回来恢复。

提交与验证：用 Live Server 打开，观察 30 秒，确认每 3～5 秒有一次明显爆发；检查粒子是否有前后遮挡、山体是否有明暗面、爆发时是否有闪光和震动；逐条核对你完成的加分项，确认没有破坏必做项。

这个练习偏综合，第一次做不完很正常，能完成几条算几条。重点是走一遍“拆任务 → 分段做 → 验收 → 迭代”的流程，不是非得一次做出完美火山。

标准提示词（供对照）： 你是资深前端开发，擅长 Canvas 2D 粒子动画。我是初学者，能看懂基础 HTML/CSS/JS，但不熟动画和粒子系统。请用原生 HTML + CSS + JavaScript 和 Canvas 2D API（不使用 Three.js、p5.js 等库，不使用外部图片和字体）做一个循环播放的猛烈火山喷发场景，画布逻辑尺寸 960 × 540，居中显示，按 devicePixelRatio 缩放。要求：火山锥有立体感，左侧受光、右侧背光，火山口为透视椭圆，山脚有阴影；粒子使用 x/y/z 伪 3D 坐标，按 z 排序绘制，近大远小、近亮远暗；每 3～5 秒爆发一次，喷出大量高速粒子，受重力呈抛物线，可飞出画布顶部后落回；每次爆发有少量带拖尾的熔岩弹、火山口强闪光、扩散冲击波和画布震动；火山灰持续向上扩散并遮挡背景；使用 requestAnimationFrame 和 deltaTime 驱动，关键逻辑加中文注释。流程：先列 TODO 给我确认，再按“场景与山体 → 粒子系统 → 爆发逻辑 → 闪光/冲击波/震动 → 火山灰 → 性能与适配”分块给代码并注明插入位置，最后给验证清单。只需兼容 Chrome / Edge 最新版。
