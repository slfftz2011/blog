上一节聊了“为什么学”，这一节干点实在的：把工具装好，把第一个页面跑起来。

你可以把写网页想象成做饭。不需要一上来就买齐整套米其林厨具，但锅、刀、砧板总得有。写网页的最小配置也一样简单：**一个浏览器、一个编辑器、一个文件夹**。就这三样，没了。

这一节的目标很实在：

- 认识浏览器自带的开发者工具，知道 Elements、Console、Styles 各看什么
- 装好 VS Code，学会“打开文件夹”而不是只打开单个文件
- 建好第一个项目文件夹，写出并打开 `index.html`
- 用 Live Server 跑通“保存 → 自动刷新”的最小循环

## 浏览器：你每天都在用，但它还有另一半

浏览器你肯定不陌生，看视频、刷新闻、查资料都靠它。但浏览器还有“另一半”——**开发者工具**，英文叫 DevTools。它是给做网页的人看的，能让你看到页面背后的结构、样式和报错。

打开方式很简单：在页面上右键，点“检查”，或者直接按 `F12`。你会看到屏幕边上弹出一大块面板，花花绿绿的代码，别慌，现在不用看懂。你只需要知道三件事：

- **Elements（元素）** 面板：能看到页面的“骨架”，鼠标指到哪行，页面上对应的块就会亮一下。
- **Console（控制台）** 面板：页面出错的时候，红字会出现在这里。以后调 bug，第一眼就看它。
- **Styles（样式）** 面板：能直接改颜色、改大小，改完立刻生效，但刷新就没了——拿来试错特别方便。

现在你只要**敢点开它**就行，不用记任何东西。就像你刚搬进新家，先知道电闸在哪，不一定要立刻会修电路。

浏览器选 Chrome 或 Edge 都行，两者都基于 Chromium 内核，DevTools 长得也很像。挑一个平时用得顺手的，别在这件事上纠结。

> 小提示：Mac 上把 `Ctrl` 换成 `Cmd`，下面提到快捷键时同理。

## 编辑器：VS Code，用着不烧心

写代码通常需要一个专门的编辑器，不过 Web 开发没那么讲究，就算你拿记事本写也没问题（只要你能忍受没高亮，引号括号只能打半边）。这边推荐使用 **VS Code**（全称 Visual Studio Code），免费、跨平台、插件多，是目前最主流的选择。更重要的是：后续我们会涉及更高阶的项目架构，届时代码量更多、语言种类也更杂。VS Code 可以适配多种开发场景，原生支持 GitHub 等等，能少走不少弯路。

去[官网](https://code.visualstudio.com/)一直划到底，点 `Download for Windows` 下载安装（其他操作系统自行选择合适版本），一路下一步就行。装好之后，先做三件小事：

1. **打开一个文件夹**。VS Code 可以打开单个文件，但做项目更推荐“打开文件夹”，左边会出现文件列表。这个习惯很重要，后面项目文件多了才不会乱。
2. **认识侧边栏**。左边那一竖条，最上面是文件列表，下面有搜索、源代码管理（Git）等图标。现在只用文件列表就够。
3. **装插件**。点左边那个方块图标，搜索并安装：
   - **Live Server**：建议装，下一节马上用到，能自动刷新页面。
   - **Chinese (Simplified) Language Pack**：可选。想要中文界面就装它，重启后生效。

主题、字体、快捷键这些，以后慢慢调。现在别把时间花在“把编辑器打扮得好看”上，先写第一行代码。

## 文件夹就是项目：目录怎么建

在你的电脑上找个顺手的地方，新建一个文件夹，名字比如 `my-first-site`。这个名字随便起，但建议：

- **用英文、数字、短横线**，别用中文和空格。不是技术上绝对不行，而是后面部署、命令行操作时容易出幺蛾子，一开始就养成习惯省事。
- 文件夹里先只放一个文件：`index.html`。

为什么叫 `index.html`？因为网站服务器通常会把 `index.html` 当作默认首页：访问一个目录时，服务器会先找它。就像一本书的“目录页”，约定俗成。你可以叫别的名字，但访问首页时往往要显式带上文件名，不如直接访问域名干净好记。所以还是老老实实按标准写。

以后文件多了，可以这样分：

```
my-first-site/
├── index.html
├── images/        ← 图片放这里
├── css/           ← 样式文件放这里
└── js/            ← 脚本文件放这里（第 2 部才用）
```

现在知道有这回事就行，不用提前建一堆空文件夹。**需要的时候再建，比先建一堆用不上要清爽。**

## 第一个网页：写、打开、看见

打开 VS Code，用“文件 → 打开文件夹”选中你的 `my-first-site`。然后在左边文件列表里右键，新建文件，命名为 `index.html`。

在文件里输入下面这段：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的第一个网页</title>
</head>
<body>
  <h1>你好，Web！</h1>
  <p>这是我亲手写的第一个页面。</p>
</body>
</html>
```

看不懂没关系，下一章会逐行讲。现在你只需要做一件事：**把它打开看看**。

有两种打开方式：

1. **直接双击 `index.html`**：会用默认浏览器打开，能看到“你好，Web！”就算成功。
2. **右键 → Open with Live Server**：如果你装了 Live Server 插件，用这个方式打开，地址栏会变成 `127.0.0.1:5500` 之类，页面也能看到。

两种都行。第一种最简单，第二种下一节细说。**先看到页面，比先搞懂原理重要。**

## Live Server：省掉手动刷新的麻烦

你可能会发现，直接双击打开的话，每次改完代码，都要手动按 `F5` 刷新浏览器才能看到变化。改十次刷十次，挺烦的。

**Live Server** 就是来解决这个的。它会在你电脑上开一个小服务，你每次保存文件，浏览器自动刷新。用法：

1. 在 VS Code 里右键 `index.html`，选 **Open with Live Server**。
2. 浏览器打开页面，地址是 `http://127.0.0.1:5500/index.html` 这种形式。`127.0.0.1` 就是“本机”的地址，意思是这个页面由你电脑上的 Live Server 提供，不是从网上下的。
3. 回去改一行字，比如把“你好，Web！”改成“你好，世界！”，按 `Ctrl + S` 保存。
4. 看浏览器——不用手动刷新，它自己变了。

这个“保存就变”的循环，会陪你走完整个系列。用顺手之后，你会觉得手动刷新是一种折磨。

不用的时候，在 VS Code 右下角点一下 **Port: 5500** 那个小按钮，选“停止”就行。不关也不会有大问题，但关掉是个好习惯。

## 最小开发循环：改 → 看 → 查 → 再改

工具齐了，页面也跑起来了。现在建立一个最重要的习惯，我把它叫**最小开发循环**：

> **改代码 → 保存 → 看浏览器 → 不对就查 → 再改**

这个循环听起来简单，但它比“一次写对”重要得多。没有人是一次写对的，包括写了十几年的人。区别只在于：熟手改得快、查得准，新手改得慢、查得懵。而查得准，靠的就是上一节说的 DevTools 和 MDN。

新手最常踩的三个坑，提前打个预防针：

- **文件路径错**：图片显示不出来，多半是路径写错了。`images/cat.jpg` 和 `./images/cat.jpg` 是一回事，`/images/cat.jpg` 是另一回事。先检查文件到底在不在那个位置。
- **没保存**：改完代码看浏览器没变，第一反应先看 VS Code 标签页上有没有一个小圆点——有圆点就是没保存。按 `Ctrl + S`。
- **浏览器缓存**：有时候改了没生效，可能是浏览器用了旧文件。按 `Ctrl + F5` 强制刷新试试。

遇到白屏或者页面乱掉，别慌。**先按 `F12` 打开 Console 看有没有红字**，红字通常会告诉你哪一行出了问题。看不懂红字也没关系，把红字复制去搜，或者后面我们聊怎么问 AI。

## 工具齐了，下一节聊方法

到这儿，你的“厨房”基本收拾好了：浏览器能看也能查，编辑器能写也能自动刷新，文件夹和第一个页面都跑通了。

接下来两节不碰太多代码，聊两件更重要的事：**为什么学 Web 不用死记硬背**，以及**AI 时代该怎么用它帮忙、又不被它带偏**。工具是手，方法是脑，先把脑子的方向调对，手才不至于白忙。
