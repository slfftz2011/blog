上一节把工具装好、第一个页面也打开了。但仅仅这样之后你可能已经碰到两个小麻烦：改完代码要手动刷新才看得到变化；写错了不知道去哪儿查。这一节就解决这两件事，外加一个更重要的技能——**遇到不会的东西，知道去哪儿找答案**。

要用的东西就三个：**Live Server、MDN、Console**。每一个都会说清楚“在哪儿点、看到什么、什么意思”。例子会用几个最简单的标签，用到时会顺带解释它是干什么的，不用提前背——这些标签和属性，后续章节都会逐一学习。

本节目标：

- 装好 Live Server，跑通“保存 → 自动刷新”的循环
- 学会在 MDN 上查一个标签或属性的用法，不再靠猜
- 认识 Console，知道页面出错时先去哪儿看红字
- 建立“改 → 看 → 查 → 再改”的最小开发循环

## Live Server：装一次，以后不用手动刷新

Live Server 是 VS Code 的一个插件。插件就是给编辑器加功能的小程序。它的作用一句话：**你保存文件，浏览器自动刷新，不用再按 F5**。

### 怎么装

打开 VS Code，看最左边那一竖条图标。其中一个长得像四个方块、有一块正在飞出去，点它，就打开了“扩展”面板。也可以按 `Ctrl + Shift + X`（Mac 是 `Cmd + Shift + X`）直接打开。

在搜索框里输入 `Live Server`。出来的第一个结果，看作者名，认准 **Ritwick Dey**。点旁边的绿色 `Install` 按钮，等几秒，按钮变成 `Uninstall` 就装好了。装完建议重启一下 VS Code，图个踏实。

### 怎么用

打开上一节建好的 `index.html`。鼠标先点进代码编辑区——这一步很关键，得让编辑器知道你在操作这个文件。然后右键，菜单里会多出一项 `Open with Live Server`，点它。

VS Code 会自动打开浏览器，地址栏里是类似 `http://127.0.0.1:5500/index.html` 的东西。注意开头是 `http://` 而不是 `file://`，说明它走的是本地小服务器，不是直接打开文件。`127.0.0.1` 就是“本机”的意思，这个页面由你电脑上的 Live Server 提供，不是从网上下的。

现在试一下：回到 VS Code，把 `<h1>你好，Web！</h1>` 里的字改掉。这里解释一下：`<h1>` 是 HTML 里的“一级标题”标签，夹在它中间的文字会变成页面最大的标题。改完按 `Ctrl + S` 保存，看浏览器——不用碰它，页面自己变了。这就是 Live Server 的全部价值：**改、存、看，循环变短了**。

### 怎么关

VS Code 右下角状态栏会显示 `Port: 5500`，点它，选 `Stop Live Server` 就停了。不关也不会有大问题，但用完停掉是个好习惯，端口不会被一直占着。

## MDN：遇到不认识的标签，来这里查

MDN 的全称是 **Mozilla Developer Network**（Mozilla 开发者网络）。Mozilla 是做火狐（Firefox）浏览器的那家组织，他们维护了一个巨大的 Web 技术文档网站。HTML、CSS、JavaScript 的每一个标签、每一条属性、每一个方法，都能在里面查到用法和示例。你可以把它当成 **Web 开发的“新华字典”**：不用背，但要会翻。

### 怎么打开

浏览器地址栏输入：

```
https://developer.mozilla.org/zh-CN/
```

或者直接点这：[MDN Web Docs](https://developer.mozilla.org/zh-CN/)

`zh-CN` 表示中文简体。右上角可以切换语言，初学先用中文版就够。

### 怎么查一个标签

假设你想在页面上放一张图片，但不知道用什么标签。在 MDN 首页搜索框输入 `img`，回车，点进 `<img>：图像嵌入元素` 这个条目。

进去之后不用被满屏内容吓到，先看三块：

1. **开头第一段**：用一两句话告诉你这个标签是干什么的。`<img>` 的开头大概会说：它把一张图片嵌入到网页里。
2. **示例**：往下滚，有能直接看的代码例子。挑一个最简单的，复制到自己页面里改一改，看会发生什么。
3. **属性**：属性就是可以往标签里加的“额外设置”。`<img>` 有两个最常用的属性：
   - `src`：告诉浏览器图片文件在哪儿，比如 `src="cat.jpg"`。
   - `alt`：一段替身文字，图片加载不出来时显示它，屏幕阅读器也会读它。

所以一张图片的标准写法是：

```html
<img src="cat.jpg" alt="一只橘猫趴在窗台上">
```

<img> 是标签名，src 和 alt 是写在标签里面的属性，等号后面的引号里是属性的值。现在不用记住，只要看出“标签 + 属性”这个结构就行。

查的时候记住一件事：你是带着问题来的。问题解决了，就关掉页面去改代码，不用把 MDN 条目从头读到尾。字典不是用来通读的，MDN 也一样。

Console：页面出问题时，先来这里看红字

Console（控制台）是浏览器开发者工具里的一个面板。网页运行出错时，错误信息会出现在这里，绝大多数时候是红色的。你不需要学会“修”所有错误，但需要知道去哪儿看。

怎么打开

在浏览器页面上按 F12。Chrome 或 Edge 会从右侧或底部弹出开发者工具。顶部有一排标签，找到 Console（控制台），点它。按 F12 没反应的话，在页面上右键 → 检查，效果一样。

Console 长什么样

打开后是一大片区域。页面没错误时，它可能是空白的，或只有一两条灰色普通提示。有错误时，会出现一行或几行红色文字，前面可能带个红色圆点图标。

错误信息通常长这样：

Uncaught ReferenceError: myFunction is not defined
at index.html:15

先别管 Uncaught 和 ReferenceError 这些英文词。看冒号后面那句白话：myFunction is not defined，意思是“myFunction 这个东西没定义，浏览器找不到它”。下面一行 at index.html:15，意思是错误发生在 index.html 的第 15 行。点一下 index.html:15 这个链接，工具会跳到 Sources 面板，把那行代码高亮出来。

现在不需要学会修。只要建立一个反射：页面不对劲 → 按 F12 → 看 Console 有没有红字 → 有红字就先读那句“什么东西 not defined / not a function / failed to load”。读不懂就把红字整段复制去搜，通常第一条结果就有人解释过同样的错误。

安全提醒：不要往 Console 里粘贴陌生人给你的代码。Console 能在当前页面上执行命令，恶意代码可能借你已登录的账号做操作。只“看”，不“粘”，就没问题。

小练习：把三件事串一遍

花三分钟，把三个工具各用一次。这个练习会故意写一个不存在的标签，看看会发生什么。

1. 打开 index.html，用 Live Server 跑起来（编辑器里右键 → Open with Live Server）。
2. 找到 `<h1>你好，Web！</h1>`，把 `h1` 改成 `h11`，变成 `<h11>你好，Web！</h11>`。`<h1>` 是一级标题标签，`<h11>` 并不存在——HTML 只有 `h1` 到 `h6` 六级标题。保存后看浏览器：文字还在，但变小了，因为浏览器不认识 `<h11>`，把它当成普通文字处理了。
3. 按 `F12` 打开 Console。有红字吗？大概率没有。因为写了一个不存在的 HTML 标签，浏览器不会报“错”，只会默默忽略。这本身是个重要认知：**不是所有问题都会在 Console 里报红**。
4. 去 MDN 搜 `h1`，确认正确写法就是 `<h1>`，标题标签只有 `h1` 到 `h6`。
5. 改回 `<h1>`，保存，浏览器自动恢复。

做完这一遍，三个工具就都用上了：**Live Server 让你看到变化，MDN 帮你确认正确写法，Console 帮你判断“这里到底有没有报错”**。
